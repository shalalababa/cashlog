# Cashlog 记账工具 · 实施计划

> 目标：替代当前的 `记账单.xlsx`，做一个本地优先、易用、录入流畅、UI 美观、可视化带动画的记账工具，并保留与 xlsx 文件的安全双向同步能力。

---

## 0. 已锁定的决策（2026-06-21）

| 项目 | 决策 |
|---|---|
| 形态 | 本地 Web 应用：FastAPI（Python）后端 + React + TypeScript + Vite 前端，浏览器访问 `localhost` |
| 数据真源 | SQLite 为唯一真源；JSON 自动镜像；xlsx 走手动双向同步（「同步到表格」/「从表格同步」），带 diff 预览 |
| 桌面化 | 先用本地 Web 跑通核心体验，后续再用 Tauri 包装为桌面应用 |
| 图表 / 动画 / 表格 | ECharts / Framer Motion / TanStack Table |
| 金额精度 | 交易原币种金额用最小货币单位整数存储；人民币换算缓存用微元（CNY * 1,000,000）存储；显示和结算边界再统一舍入 |

预算（#11）和仪表板（#12）纳入长期范围，但不是 MVP 阻塞项。先完成数据、同步、录入、AA、统计可视化，再做预算和首页仪表板。

当前环境已核对：Node v22.15.0、npm 10.9.2、Python 3.11、FastAPI 0.100.0、uvicorn 0.23.0、openpyxl 3.1.2。

## 1. 现有表格分析

原 `记账单.xlsx` 的结构：

| 工作表 | 结构 / 逻辑 |
|---|---|
| 支出 | 日期 / 金额 / 币种 / 消费内容 / 分类 / 人民币换算 / 当日汇率。当前没有结构化 AA 列，AA 只出现在 `消费内容` 文本里。 |
| 入账 | 同支出结构，列名为「入账来源」。存在半录入/异常行，部分行缺少汇率或人民币换算。 |
| 统计 | 财政月以每月 5 日为结尾；`SUMIFS` 汇总 `[上月5日, 本月5日)` 的人民币金额，排除「学费」「特殊」分类；按 5 日汇率换算美元；信用卡美元金额手动录入；信用卡占比可超过 100%。 |
| 汇率 | (日期, 币种, 对人民币汇率)。换算取「不晚于交易日的最近一条汇率」。 |
| 亚马逊计算器 | 按税前金额比例分摊税：`税后单项 = 总价 * 税前单项 / 税前合计`。 |
| AA计算器 | 多名参与人 + 两两/全员共享桶 + 税；先拆分共享项，再按比例分摊税。亚马逊计算器是它的严格子集。 |

迁移时需要注意：
- 支出包含多个币种。
- `消费内容` 中含 `AA` 的支出需要识别为 AA 候选，并支持批量补结构化字段。
- 汇率表可能早于最新支出就停止更新，此后的外币支出会沿用最后一条汇率；迁移报告必须明确标记这类汇率跨度。

必须保留的非显性语义：
- 财政月以 5 日结尾，统计区间是 `[上月5日, 本月5日)`。
- 统计默认排除「学费」「特殊」，用分类上的 `exclude_stats` 表示。
- 汇率换算取「不晚于交易日的最近一条」。
- 信用卡占比允许超过 100%。
- AA 计算器按税前金额比例分摊税；亚马逊计算器并入 AA/小票计算器。

## 2. 为什么不用飞书多维表格

| 需求 | 飞书多维表格 |
|---|---|
| 本地优先 + 本地 xlsx 文件双向同步 | 仅云端；可导入导出 xlsx，但不能天然和本地文件可靠双向同步 |
| AA 最优转账简化 | 公式/看板不适合做债务图求解，仍需自研逻辑 |
| 按比例分摊税的 AA / 亚马逊计算器 | 可以硬做公式，但交互和复用都弱 |
| Excel 式智能前缀补全 | 不可按本项目规则定制 |
| 历史每日汇率换算 | 需要额外自动化和汇率表维护 |
| 定制动画可视化 | 只能使用固定看板能力 |
| 财政月 5 日结尾统计 | 可做但公式复杂、可维护性差 |

结论：飞书适合作为未来可选的云端展示镜像，不作为主账本或同步核心。

## 4. 数据模型

完整 DDL 见 [schema.sql](schema.sql)，代表性查询见 [queries.sql](queries.sql)。核心表：

- `currency`：币种，包含 `minor_unit`，例如 CNY/USD/HKD 为 2，JPY 为 0。
- `exchange_rate`：按日期存汇率，`rate_to_base` 用文本保存精确十进制，由应用层用 `Decimal` 计算。
- `category`：分类，包含颜色、图标、`exclude_stats`。
- `person`：AA 参与人。
- `txn`：合并支出和入账，用 `direction` 区分；包含稳定 `external_uid`、同步 hash、修订号、金额整数、汇率缓存和人民币微元缓存。
- `txn_participant`：每笔 AA 的参与人和最终应付金额；`weight` / `fixed_amount_minor` 仅保留拆分来源，`owed_amount_minor` 是可审计结果。
- `fiscal_month`：手动信用卡金额，其余统计派生。
- `aa_session` / `aa_session_item` / `aa_session_item_share`：AA/小票计算器草稿和参与人分摊。
- `setting`：应用设置。

数据完整性约束：
- `txn.category_id` 允许为空，但统计查询必须把空分类归入「未分类」，不能悄悄漏算。
- `category.kind` 必须和 `txn.direction` 一致，由数据库触发器或数据层校验保证。
- `txn.external_uid` 是 xlsx/JSON/SQLite 之间识别同一条交易的稳定身份。
- `revision` 由应用层每次修改递增；`updated_at` 使用高精度时间戳，只做展示和辅助排序，不单独作为冲突判断依据。

### sql-code-review 决策

| 优先级 | 问题 | 决策 |
|---|---|---|
| 高 | 金额不能用浮点承载结算 | 原币种金额存最小单位整数，人民币缓存存微元；业务层用 `Decimal` 计算。 |
| 高 | xlsx 行匹配不能只靠内容/日期/金额 | P1 就写入稳定 `external_uid`，导出时放入隐藏列或 sidecar 映射。 |
| 中 | 自动补全 `LIKE :prefix` 可能被 `%`/`_`/`\` 干扰 | 应用层转义，SQL 使用 `ESCAPE '\'`。 |
| 中 | 分类为空时统计漏算 | 查询使用 `LEFT JOIN` + `COALESCE`，未分类作为独立桶显示。 |
| 中 | AA 小票共享人不能只存在 JSON 里 | 规范化为 `aa_session_item_share`，便于校验、重算、生成交易。 |
| 低 | 单用户本地 SQLite 权限模型简单 | 仍坚持所有 SQL 参数化，不拼接用户输入。 |

## 5. 同步设计

同步身份必须在 P1 完成，不能等到后期再补。

- SQLite 是真源；JSON 镜像每次提交变更后自动写出，便于 diff 和备份。
- xlsx 手动双向同步，两个按钮：
  - 「同步到表格」：DB -> `记账单.xlsx`，保留原有工作表布局，重建 `人民币换算` / `当日汇率` 公式，并写入隐藏同步列。
  - 「从表格同步」：`记账单.xlsx` -> DB，先展示 diff 预览（新增、修改、删除候选、冲突、异常行），确认后写入。
- 稳定身份：
  - 优先使用隐藏列 `_cashlog_uid`。
  - 老 xlsx 初次导入时没有 UID，导入器为每条有效交易生成 UID。
  - 初次导出会把 UID 写回 xlsx，同时写前备份原文件。
- 冲突判断：
  - 每条交易保存 `revision`、`updated_at`、`last_synced_at`、`last_xlsx_hash`。
  - 从 xlsx 导入时，如果 DB revision 和上次同步状态都变化，显示冲突，不自动覆盖。
  - Excel 行顺序变化不视为冲突；内容 hash 变化才参与 diff。
- 文件安全：
  - 写入前生成带时间戳的 `.xlsx` 备份。
  - 如果 Excel 正在打开导致文件锁定，不强写，提示关闭或另存。
  - xlsx 写入失败不能影响 SQLite 中已提交的数据。

## 6. 功能落地规则

1. 智能补全：按历史 `content` 前缀匹配，按频次 + 最近使用排序。多个候选时显示下拉，不强行 ghost-text；只有唯一候选时才行内补全。
2. 多币种换算：`exchange_rate` 表取不晚于交易日的最近汇率；如果最近汇率距交易日超过阈值（默认 7 天），在迁移和录入界面标记为需要确认。
3. 分类：应用内管理分类、颜色、图标和 `exclude_stats`；未分类交易允许存在但必须显式显示。
4. AA 追踪：`is_aa` / `payer_id` / `aa_settled` / `txn_participant` 共同表达；未结清视图按原币种显示，不换算人民币。
5. AA 最优转账：按币种分组，先计算每人净额，再用贪心匹配债务人和债权人；支持全部未结清或选中条目。
6. AA/小票计算器：录入税前小项、共享人、税费/总价；税费按税前金额比例分摊，结果生成 `owed_amount_minor`，可一键生成 AA 交易。
7. 亚马逊计算器：并入 AA/小票计算器的「单付款人 + 按比例分税」预设。
8. 财政月统计：区间 `[上月5日, 本月5日)`；排除 `exclude_stats`；按财政月结尾日汇率换算美元；信用卡金额手动录入，信用卡占比允许超过 100%。
9. 可视化：ECharts 支持分类矩形树图/环形图、支出趋势、分类金额趋势、分类占比趋势；范围可选财政月或自由日期。
10. 主列表：TanStack Table 支持日期、分类、币种、AA 状态、金额、文本筛选；多列排序；列显隐。
11. 预算：P6 后做，总体预算 + 分类预算，支持百分比或绝对值。
12. 仪表板：P6 后做，本月累计 vs 上月、主要分类占比、预算进度。

## 7. 分阶段实施计划

### P1：数据核心与同步身份

**目标**：建立可验证的数据底座，保证 xlsx -> SQLite 的初次迁移可审计。

任务：
1. 建立 SQLite schema、迁移脚本和基础 seed（币种、分类、默认本人）。
2. 实现 xlsx 只读导入，生成 `external_uid`、行 hash 和迁移报告。
3. 对账 `支出` 的金额、汇率、人民币换算；列出 `入账` 异常行、缺汇率行、长跨度汇率行、AA 候选行。
4. 实现 JSON 镜像导出。

验收：
- 支出全部导入，金额/汇率/人民币换算差异在定义阈值内。
- 入账全部进入报告，异常行不被静默当作正常数据。
- 全部 AA 文本候选可在报告中看到。
- 每条有效交易都有稳定 `external_uid` 和 `revision`。

### P2：最小 xlsx 往返同步

**目标**：先证明同步协议可靠，再让 UI 产生大量数据。

任务：
1. 「同步到表格」写入隐藏 `_cashlog_uid`、重建支出/入账/汇率/统计表。
2. 「从表格同步」按 UID + hash 生成 diff 预览。
3. 实现写前备份、文件锁定提示、冲突检测。

验收：
- xlsx 行重排后导入不产生误新增。
- 修改一条 Excel 交易后 diff 准确显示 1 条修改。
- DB 和 xlsx 同时修改同一条交易时显示冲突，不自动覆盖。
- 写入失败不会破坏 SQLite 数据或原 xlsx 备份。

### P3：日常录入体验

**目标**：让工具达到日常可用。

任务：
1. 主列表只读视图：分页/虚拟滚动、筛选、排序、列显隐。
2. 新增/编辑交易：日期、方向、金额、币种、内容、分类、备注。
3. 智能补全：前缀建议、唯一候选 ghost-text、键盘确认。
4. 分类和币种管理：新增、禁用、排序、颜色/图标。

验收：
- 可以不打开 Excel 完成新增、编辑、筛选、排序。
- 输入 `Chat` 时能看到相关候选；输入到唯一前缀时才行内补全。
- 未分类和异常汇率状态在主列表可见。

### P4：AA 套件

**目标**：把文本 AA 升级为结构化 AA，并支持未结清转账。

任务：
1. 参与人管理和编辑交易时即时新建参与人。
2. 交易 AA 标记、付款人、参与人、应付金额、是否结清。
3. 未结清 AA 视图和按币种最优转账算法。
4. AA/小票计算器，支持税前小项、共享人、税费分摊、一键生成 AA 交易。
5. AA 文本候选批量补结构化字段。

验收：
- 可把历史 AA 候选逐条或批量补成结构化 AA。
- 同一批未结清 AA 能输出按币种分组的最简转账方案。
- 非平均 AA 能保存最终应付金额，并可复算和审计。

### P5：统计与可视化

**目标**：替代当前 `统计` 表，并提供交互式图表。

任务：
1. 财政月统计引擎：支出、美元换算、信用卡金额、占比。
2. 分类占比：矩形树图 + 环形图，支持勾选分类。
3. 趋势图：总支出按天/周/月，分类金额/占比趋势。
4. 图表空状态、异常汇率提示和动画过渡。

验收：
- 财政月统计和现有 Excel 统计在同一规则下对得上。
- 可自由选择日期范围或财政月范围。
- 图表能排除/恢复特定分类。

### P6：预算、仪表板与桌面化

**目标**：在核心账本稳定后增加规划和入口体验。

任务：
1. 预算表：总体预算 + 分类预算，支持百分比和绝对值。
2. 仪表板：首页展示本月/上月、主要分类、预算进度、AA 未结清提醒。
3. Tauri 打包桌面版。
4. 可选：飞书云端展示镜像。

验收：
- 预算不影响历史统计口径。
- 桌面版能读写同一 SQLite/JSON/xlsx 路径。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 金额精度错误 | AA 结算和统计不可信 | 用整数最小单位 + 人民币微元，所有计算集中在 Decimal 服务层。 |
| xlsx 同步误匹配 | 重复交易被覆盖或误新增 | P1 写入稳定 UID；P2 完成往返同步后再做大规模 UI。 |
| 汇率缺口被掩盖 | 后续支出沿用过旧汇率 | 迁移报告和录入界面标记超过阈值的汇率跨度。 |
| Excel 公式与应用计算不同 | 用户不信任迁移结果 | P1 逐行对账，保留公式导出，使 xlsx 可独立打开核对。 |
| AA 历史迁移成本高 | 大量候选手工补录负担大 | 提供 AA 候选报告和批量结构化工具。 |
| 范围过大 | 核心账本迟迟不可用 | 预算、仪表板、Tauri、飞书镜像都放到 P6。 |
